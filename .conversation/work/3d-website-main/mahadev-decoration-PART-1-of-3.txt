BUSINESS CONTEXT & GOAL
────────────────────────────────────────────────────────────────
Today customers book only via phone calls and WhatsApp — no digital
trail, no structured pricing, no way to check availability, high
manual chaos for the owner. This platform must digitize the funnel
end-to-end while keeping WhatsApp as an always-available fallback,
never removing it.

Target funnel:
Discover site → browse real past work → pick event type → see
packages/starting prices → pick a date → check availability → submit
requirements → admin sends quotation → customer approves → advance
payment → booking confirmed → customer tracks status on a timeline →
event happens → remaining payment recorded → review collected →
completed event becomes a new portfolio entry.

PERFORMANCE & MOTION RULES (non-negotiable, apply to everything)
────────────────────────────────────────────────────────────────
- Cinematic look must never cost smoothness. Target excellent Core
  Web Vitals on a mid-range Android phone, not just desktop Chrome.
- Lazy-load every heavy section (3D canvas, gallery masonry images,
  below-the-fold content) with intersection-observer based mounting.
- All images: next/image, responsive srcset, compressed, explicit
  width/height to avoid layout shift.
- Detect low-end devices / prefers-reduced-motion and degrade
  gracefully: fewer particles, no 3D canvas, simpler transitions —
  never a broken or empty page.
- If WebGL is unsupported, render a beautiful static image/gradient
  fallback in place of every 3D element — no blank boxes.
- Motion language, defined once and reused everywhere:
  • Entrances: fade + 16–24px slide, ~500–700ms, ease-out
  • Cards: lift 4–8px + soft shadow/gold-glow on hover, ~250ms
  • Images inside cards: slow zoom (scale 1 → 1.06) over the hover
    duration, never a snap
  • Headings: elegant staggered word/line reveal on scroll-in
  • Buttons: subtle magnetic hover (small cursor-follow offset),
    no bounce, no spin, no flashing
  • Scroll reveals: once-per-element (don't re-trigger on scroll-up
    unless intentionally used for the step-progress line)
  Every animation must justify itself with a purpose (draw attention,
  show hierarchy, confirm an action) — no decoration for its own sake.

3D EXPERIENCE — STRATEGIC ONLY
────────────────────────────────────────────────────────────────
Build these as isolated, lazy-loaded R3F scenes with their own
loading + reduced-motion + no-WebGL fallbacks:
1. Hero background depth layer: soft floating flower-petal particles
   + gentle bokeh light points drifting behind the hero photo, with a
   subtle camera-parallax on mouse move / device tilt. Keep particle
   count low (mobile: near-zero or fully static fallback).
2. "Choose your occasion" cards: a light 3D tilt-on-hover effect
   (CSS 3D transform is fine here, R3F not required) synced with the
   gold border glow.
3. Booking Success page (Part 2): a brief, tasteful 3D
   flower/confetti celebration burst — plays once, auto-stops, skip
   button available.
Nowhere else. Do not turn the site into an interactive game or add
3D to sections where it doesn't add real value.
